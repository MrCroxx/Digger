# DMG Installer UI (Drag to Applications)

This session added a DMG-based installer experience for Digger so users see the standard drag-to-Applications window when packaging, without opening Finder during build.

## What was implemented

- DMG packaging step in `scripts/build-app.sh` that creates a distributable `Digger-<version>.dmg` alongside the `.app` bundle.
- npm create-dmg support for a modern DMG (standard layout, no custom background).
- Finder layout and icon positioning fallback for the DMG window (Digger on the left, Applications on the right).
- Optional background image for the DMG window, generated by a small Swift/AppKit script.
- Ability to keep packaging fully silent (no Finder window auto-open during build).

## How it works

1. The app bundle is built as before.
2. If npm `create-dmg` is available, it is used to create the DMG with its standard layout.
3. Otherwise, a staging directory is created and populated with:
   - `Digger.app`
   - A symlink to `/Applications`
   - Optional `.background/dmg-background.png`
4. A temporary read-write DMG is created from the staging directory using `hdiutil`.
5. (Optional) Finder is used to set the window layout, icon positions, and background.
6. The DMG is detached and converted to a compressed image for distribution.

## Background image generation

The background is generated at build time by a Swift script using AppKit drawing APIs. The script renders into an in-memory bitmap and exports PNG data.

- Script: `scripts/dmg-background.swift`
- Output: `dist/dmg-background.png`
- Design: light textured gradient, arrow pointing left-to-right, and a short instruction text.

If the script fails (missing Swift, AppKit, etc.), packaging continues without the background.

## Configuration switches

- `CREATE_DMG=1` (default): enable DMG creation.
- `CREATE_DMG=0`: skip DMG creation.
- `USE_CREATE_DMG=1` (default): prefer npm `create-dmg` installed via `npm install --global create-dmg` (requires Node.js 20+).
- `USE_CREATE_DMG=0`: skip npm `create-dmg` and use the Finder-based layout instead.
- `GENERATE_DMG_BG=0`: do not render a background image during packaging.
- `GENERATE_DMG_BG=1` (default): render `dist/dmg-background.png` using the Swift script.
- `CONFIGURE_DMG=0` (default): do not open Finder to configure the window during build.
- `CONFIGURE_DMG=1`: open Finder to apply layout/background and icon placement (only used when `USE_CREATE_DMG=0`).

Example:

```bash
  CREATE_DMG=1 GENERATE_DMG_BG=1 USE_CREATE_DMG=0 CONFIGURE_DMG=1 scripts/build-app.sh
```

Silent DMG build (default behavior):

```bash
  scripts/build-app.sh
```

## Key files

- `scripts/build-app.sh`
- `scripts/dmg-background.swift`

## Notes

- The installer UI is a Finder DMG window, not a SwiftUI runtime view.
- Background and layout are applied by Finder when `CONFIGURE_DMG=1` (npm `create-dmg` does not support custom layout/background).
- Install npm `create-dmg` with `npm install --global create-dmg`.
- The brew `create-dmg` binary is ignored; only the npm global install is used.
- If you want a fully silent build and still have a custom layout, consider pre-baking a `.DS_Store` file into the DMG (not implemented here).

## Layout tuning

The layout is driven by a single icon size and explicit positions. These values are only used by the Finder-based layout.

- `DMG_ICON_SIZE`: icon size for both items (default: 96)
- `DMG_APP_POS_X`, `DMG_APP_POS_Y`: app icon position
- `DMG_APPS_POS_X`, `DMG_APPS_POS_Y`: Applications icon position

These values live in `scripts/build-app.sh` and are used by the Finder fallback.
