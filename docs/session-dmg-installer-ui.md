# DMG Installer UI (Drag to Applications)

This session added a DMG-based installer experience for Digger so users see the standard drag-to-Applications window when packaging.

## What was implemented

- DMG packaging step in `scripts/build-app.sh` that creates a distributable `Digger-<version>.dmg` alongside the `.app` bundle.
- Finder layout and icon positioning for the DMG window (Digger on the left, Applications on the right).
- Optional background image for the DMG window, generated by a small Swift/AppKit script.
- Ability to keep packaging fully silent (no Finder window auto-open during build).

## How it works

1. The app bundle is built as before.
2. A staging directory is created and populated with:
   - `Digger.app`
   - A symlink to `/Applications`
   - Optional `.background/dmg-background.png`
3. A temporary read-write DMG is created from the staging directory using `hdiutil`.
4. (Optional) Finder is used to set the window layout, icon positions, and background.
5. The DMG is detached and converted to a compressed image for distribution.

## Background image generation

The background is generated at build time by a Swift script using AppKit drawing APIs.

- Script: `scripts/dmg-background.swift`
- Output: `dist/dmg-background.png`
- Design: light textured gradient, arrow pointing left-to-right, and a short instruction text.

If the script fails (missing Swift, AppKit, etc.), packaging continues without the background.

## Configuration switches

- `CREATE_DMG=1` (default): enable DMG creation.
- `CREATE_DMG=0`: skip DMG creation.
- `CONFIGURE_DMG=0` (default): do not open Finder to configure the window during build.
- `CONFIGURE_DMG=1`: open Finder to apply layout/background and icon placement.

Example:

```bash
CONFIGURE_DMG=1 scripts/build-app.sh
```

## Key files

- `scripts/build-app.sh`
- `scripts/dmg-background.swift`

## Notes

- The installer UI is a Finder DMG window, not a SwiftUI runtime view.
- Background and layout are applied by Finder when `CONFIGURE_DMG=1`.
- If you want a fully silent build and still have a custom layout, consider pre-baking a `.DS_Store` file into the DMG (not implemented here).
